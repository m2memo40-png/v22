# سجل إصدارات Fluxmax — آخر إصدار مصدر هو v22

سجل v16 أثبت نجاح دخول النواة والصدفة والاختبارات الذاتية (14/14)، وتشغيل برنامج Ring 3، وDHCP وPing وDNS. بقي اختبار المتصفح يفشل عند إرسال طلب HTTP ويطبع `request send failed`. لم يكن سجل الفشل يوضح هل فشل الإرسال محليًا، أم أعاد الطرف الآخر RST، أم انتهت مهلة ACK.

## تغييرات v17

- جعل `pending_valid` آخر حقل يُنشر بعد تجهيز رقم التسلسل والحمولة وموعد إعادة الإرسال، منعًا لأن يقرأه خيط استطلاع الشبكة في منتصف تجهيز المقطع.
- يبدأ موعد إعادة الإرسال قبل إرسال المقطع، بدل تحديثه بعد العودة من مسار الإرسال، لتفادي إعادة إرسال مبكرة من مهمة الشبكة عند وجود preemption.
- إصلاح تنظيف حالة اتصال TCP إذا فشل إرسال SYN محليًا.
- إضافة كود خطأ TCP واضح إلى رسالة المتصفح: عطل إرسال محلي (`-1`)، انتهاء مهلة ACK/إعادة الإرسال (`-2`)، إعادة ضبط من الطرف الآخر (`-3`)، أو انتهاء مهلة الإرسال (`-4`).
- تعديل اختبار QEMU لإخراج خطأ المتصفح فور ظهور أول علامة فشل بدل انتظار 25 ثانية، وطباعة سجل خادم HTTP المضيف إذا فشل اختبار HTTP. هذا يميز بين عدم وصول الطلب إلى الخادم ووصوله مع فشل الاستجابة.

## نتائج التحقق المحلي

تم بناء النواة من المصدر وتشغيل اختبارات المضيف والتحقق من ELF. بيئة العمل لا توفر `qemu-system-x86_64` ولا `xorriso`، لذلك لا أدعي أن HTTP smoke أو الإقلاع الفعلي أصبح ناجحًا. يجب تشغيل GitHub Actions على هذا الإصدار؛ سيوفر السجل الجديد كود خطأ TCP وسجل الخادم لتحديد ما إذا كان الإرسال المحلي أم ACK/الطرف المضيف هو المتسبب.


## تغييرات v18
- أكد سجل v17 أن خادم الاختبار استقبل الطلب وأعاد HTTP 200، رغم أن الضيف أعلن فشل إرسال TCP.
- أصبح `CLOSE_WAIT` صالحًا لانتظار اكتمال ACK وإرجاع نجاح الإرسال بعد استلام FIN من الطرف الآخر.
- أُضيف اختبار انحدار يعيد سيناريو ACK+PSH+FIN معًا أثناء الإرسال ويتحقق من استمرار إمكانية قراءة الرد.
- مشغل QEMU ينتظر رسالة تشخيص TCP كاملة حتى يحتفظ برقم الخطأ وسببه.
- اجتازت اختبارات المضيف 111/111 وبناء النواة وفحوص ELF وLimine. لم يتم اختبار ISO v18 في QEMU داخل هذه البيئة؛ النتيجة النهائية تعتمد على GitHub Actions.


## v20 — توسيع تعريفات الشبكة وفحص الاتصال
- إضافة تعريف Intel E1000/8254x بوضع الاستطلاع مع حلقات DMA للإرسال والاستقبال، واختيار E1000 تلقائيًا عند وجوده ثم RTL8139.
- تحديث `net` لعرض اسم البطاقة الفعلي وعدّادات RX/TX، وإضافة الأمر `internet` لفحص البوابة ومحاولة DNS.
- إضافة اختبارَي إقلاع QEMU مستقلين في GitHub Actions: واحد RTL8139 وآخر E1000، ويشترط كل منهما DHCP وPing وDNS وجلب HTTP.
- عرض دقة framebuffer في نافذة النظام. لا يزال العرض عامًا من Limine وليس تعريف تسريع GPU أصليًا.
- تحقق محلي: بناء النواة وELF واختبارات المضيف 111/111. لم تتوفر QEMU/xorriso محليًا، لذلك لا أدعي تشغيل الشبكة/الإقلاع الحي حتى ينجح CI.
- لا يزال TLS/HTTPS والمتصفح الحديث غير مدعومين؛ لذلك لا تضمن هذه النسخة فتح معظم المواقع الحديثة.


## تحديث إضافي داخل v20 — الفأرة واختبارات لينكس
- إضافة تعريف فأرة PS/2 اختيارية مع IRQ12 ومحلّل حزم يتحقق من بداية الحزمة ويتجاهل قفزات الحركة عند overflow.
- إضافة مؤشر فأرة لسطح المكتب: تركيز النوافذ بالنقر، تشغيل اختصارات شريط المهام، أزرار التصغير/التكبير/الإغلاق وسحب النافذة من شريط العنوان.
- إضافة 11 اختبارًا لمحلّل بروتوكول الفأرة. الاختبارات الكلية أصبحت 122/122 ناجحة، مع بناء النواة وملف المستخدم ELF.
- لا يوجد اختبار تشغيل حي لمسار IRQ12 لأن QEMU غير متاح في بيئة البناء.
- Wi-Fi وHTTPS/TLS والتحقق من الشهادات لم تُنفّذ بعد؛ لذلك لا تزال هذه النسخة غير مكتملة للإنترنت الحديث.


## v21 — إصلاح جدولة سطح المكتب بعد SHELL_READY
- كشف سجل QEMU أن النواة أقلعت ووصلت إلى `SHELL_READY`، لكن سطح المكتب لم يطبع علامة بدء مدير النوافذ، ولم يظهر prompt.
- نقل حلقة سطح المكتب إلى مهمة kernel مجدولة؛ صار سياق الإقلاع حلقة خمول بدل تشغيل تطبيق foreground من السياق الذي لا يعيد المجدول جدولته.
- إضافة علامات debugcon `FLUXMAX:DESKTOP_TASK_QUEUED` و`FLUXMAX:DESKTOP_TASK_ENTER` لتحسين تشخيص محاولات QEMU التالية.
- تحقق محلي: 122/122 اختبار مضيف، وبناء kernel ELF وفحص Limine/ELF وSyntax ناجح. لا يتوفر QEMU/xorriso محليًا، ولذلك لا يُدعى نجاح ISO أو التشغيل الفعلي حتى ينجح GitHub Actions.


## v22 — إصلاح وميض المؤشر وإعداد الكيبورد وتجهيز اختبار الإدخال الحقيقي
- السبب الأقرب للوميض: كانت حركة الماوس تؤدي إلى مسح كامل الشاشة وإعادة رسم النوافذ مباشرةً داخل framebuffer. أصبحت إطارات سطح المكتب تُرسم أولًا في ذاكرة RAM ثم تُعرض دفعة واحدة؛ وحركة المؤشر العادية تحفظ وتستعيد مساحة المؤشر الصغيرة بدل إعادة رسم الشاشة بالكامل.
- تحسين سرعة الرسم بكتابة المستطيلات صفًا بصف بدل حساب موقع كل بكسل في كل مرة. تمت زيادة heap حتى يمكن تخصيص مخزن إطار معقول على دقات الشاشة الشائعة.
- إعداد متحكم PS/2 صراحةً لتفعيل IRQ1 وترجمة Set-1، مع مسار استعادة يحاول إعادة تفعيل منفذ الكيبورد عند فشل التهيئة. إصلاح مفاتيح Shift يمين/يسار، وكبح تكرار Caps Lock، وتجاهل رموز التنقل الموسعة بأمان ضمن واجهة إدخال النص الحالية.
- تبسيط سطح المكتب عند الإقلاع: نافذة واحدة، أيقونات تشغيل على سطح المكتب وشريط تطبيقات أسفل الشاشة. هذه واجهة مخصصة بسيطة وليست XFCE/GNOME ولا بديلًا مكتملًا للينكس.
- إضافة 10 اختبارات للإطار الرسومي و19 اختبارًا لخريطة الكيبورد، فارتفع عدد اختبارات المضيف إلى 152/152. اجتاز `make test` و`make check` محليًا، وتم فحص صياغة مشغل Python.
- تعديل QEMU smoke driver ليحقن حركة ماوس عبر HMP ومفتاح `q` عبر PS/2 وينتظر علامات debugcon من مسار الإدخال الحقيقي. لم يتوفر QEMU أو xorriso في بيئة التحرير، لذلك لم يُختبر ISO v22 فعليًا بعد؛ يلزم نجاح GitHub Actions قبل إعلان نجاح الماوس والكيبورد بصريًا.
