# بيان التنفيذ — Fluxmax v21

## تحديث v21: إصلاح تعطل بدء سطح المكتب في QEMU
- كان `desktop_run()` يعمل من سياق الإقلاع مباشرةً بعد تفعيل المقاطعات. إذا نقل المجدول التنفيذ إلى مهام shell والشبكة، فلا يعود إلى سياق الإقلاع ما دامت المهام جاهزة؛ لذلك لم تظهر علامة بدء مدير النوافذ رغم الوصول إلى `SHELL_READY`.
- أصبح سطح المكتب مهمة kernel مستقلة عبر `process_spawn()`، وأصبح سياق الإقلاع حلقة خمول.
- أضيفت علامتا debugcon `FLUXMAX:DESKTOP_TASK_QUEUED` و`FLUXMAX:DESKTOP_TASK_ENTER` لتحديد تقدم التنفيذ.
- اجتازت نسخة المصدر اختبارات المضيف 122/122 وبناء ELF وفحوص المصدر وLimine محليًا. لم يتوفر QEMU/xorriso هنا، لذلك يتطلب الإصلاح تأكيدًا في GitHub Actions ولا يُعد نجاح الإقلاع مؤكدًا بعد.


## تحديث v20: الشبكة والرسوميات
- إضافة تعريف polling أولي لـ Intel E1000/8254x مع اختيار E1000 أولًا ثم RTL8139 عند الفشل.
- إضافة أمر `internet` لتشخيص وجود كارت شبكة وعنوان IPv4 واختبار ICMP للبوابة وDNS لـ `example.com`.
- إضافة اختبارَي QEMU إلى GitHub Actions لموديلَي RTL8139 وE1000، ويشترطان DHCP وPing وDNS وHTTP محليًا.
- يظل سطح المكتب يستخدم framebuffer عامًا من Limine ولا يتضمن تسريعًا أصليًا لـ Intel/AMD/NVIDIA.
- يظل المتصفح HTTP فقط بلا TLS/HTTPS أو JavaScript/CSS/صور، ولم يتم تأكيد الإقلاع الحي محليًا لعدم توفر QEMU/xorriso.

## سجل v19: ما أُضيف سابقًا
- إعداد Limine يطلب وضع framebuffer بدقة 1024x768 وعمق 32-bit، مع السماح للمحمّل باختيار وضع بديل إذا لم يتوفر المقاس المطلوب.
- يبدأ سطح المكتب المخصص تلقائيًا عندما يعيد Limine شاشة RGB متوافقة.
- يعمل أمرَا `desktop` و`web` على فتح الواجهة الرسومية. يخرج المستخدم إلى الصدفة بالمفتاح `q`.
- الصدفة الخلفية لا تستهلك ضغطات PS/2 ولا ترسم فوق سطح المكتب أثناء عمل الواجهة.
- فحص QEMU يتوقع علامة بدء سطح المكتب ثم يخرج منه عبر COM1 قبل اختبارات الصدفة والشبكة؛ لن يعتبر الإقلاع النصي وحده نجاحًا لاختبار الرسوميات.

## حدود الرسوميات والمتصفح
- الرسوميات الحالية framebuffer عام يوفّره Limine/UEFI/BIOS؛ وليست تعريفًا مباشرًا أو تسريعًا لـ Intel أو AMD أو NVIDIA، ولا يوجد تسريع 2D/3D أو مؤشر فأرة.
- المتصفح مخصص لطلبات HTTP العادية وعرض نص HTML. لا يدعم HTTPS/TLS أو JavaScript أو تخطيط CSS أو الصور أو ملفات تعريف الارتباط.
- توجد نافذة نظام وملفات وشبكة وويب، لكن هذا لا يجعل النواة نظامًا يوميًا مكتملًا ولا يدعم جميع المواقع والمهام اليومية بعد.

## نتائج التحقق المحلي
- بناء النواة وELF: ناجح.
- اختبارات المضيف: 111/111 ناجحة.
- فحص إعدادَي Limine وملفات Python/Bash: ناجح.
- لم يتوفر QEMU أو xorriso في بيئة التحرير؛ لذلك لم يُنشأ ISO جديد ولم يُشاهد الإقلاع الرسومي فعليًا هنا. يجب أن ينجح فحص QEMU في GitHub Actions قبل اعتبار مسار GUI متحققًا أثناء التشغيل.


## تحديث v20: دعم الفأرة
- أُضيفت فأرة PS/2 اختيارية على IRQ12 مع محلّل بروتوكول مستقل قابل لاختبار المضيف.
- يعرض سطح المكتب مؤشرًا، ويستجيب للنقر على شريط المهام وأزرار عنوان النافذة، ويتيح سحب النوافذ.
- اختبارات المضيف الآن 122/122؛ تم البناء محليًا على لينكس.
- لم يُختبر IRQ الفأرة أثناء الإقلاع الفعلي، لعدم توفر QEMU/xorriso. ولا تزال Wi-Fi وHTTPS/TLS والتحقق من الشهادات غير منفذة.
