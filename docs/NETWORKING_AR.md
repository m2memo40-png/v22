# الشبكة والمتصفح في Fluxmax المستقل v21

## التعريفات والبروتوكولات
يدعم المسار الحالي بطاقتين سلكيتين في وضع polling: Intel 8254x/E1000 المتوافقة (بما فيها محاكي QEMU `e1000` من فئة 82540EM)، ثم Realtek RTL8139 كخيار احتياطي. يستخدم المسار Ethernet II وARP وIPv4 (من دون إعادة تجميع fragments) وICMP وUDP وDHCP وDNS A lookup واتصال TCP صادرًا واحدًا لغرض HTTP البسيط.

أوامر التشخيص:

```text
net
internet
netconfig dhcp
ping 10.0.2.2
resolve example.com
dns 8.8.8.8
browser http://host/path
```

`net` يعرض تعريف البطاقة، وMAC، وعنوان IP، والبوابة، وDNS، وعدّادات الإرسال والاستقبال. `internet` يختبر رد ICMP من البوابة ويحاول حل `example.com` عبر DNS. قد تمنع بعض الشبكات ICMP؛ لذلك عدم رد `ping` وحده لا يثبت انقطاع الإنترنت. نجاح إعداد IPv4 وحده أيضًا لا يثبت إمكانية الوصول إلى الإنترنت العام.

مع QEMU user networking قد تكون عناوين الضيف/البوابة/DNS هي `10.0.2.15` و`10.0.2.2` و`10.0.2.3`، لكن استخدم القيم التي يعرضها `net` فعليًا.

## المتصفح
`browser http://host/path` يرسل GET عبر DNS/TCP/HTTP ويعرض نص HTML كنص مبسط؛ ويمكن فتحه من نافذة Web في سطح المكتب. هذا ليس متصفحًا حديثًا. لا يوجد TLS/HTTPS أو تحقق شهادات أو JavaScript أو تخطيط CSS أو عرض صور أو دعم متكامل للكوكيز/المصادقة/إعادة التوجيه. لا ترسل كلمات مرور أو أي بيانات حساسة عبر HTTP.

## الشاشة
يستخدم سطح المكتب framebuffer RGB عام يقدمه Limine، ويمكنه الرسم برمجيًا على وضع العرض الذي وفره محمّل الإقلاع. هذا يسمح بعرض الواجهة الأساسية دون تعريف تسريع خاص بالشركة المصنّعة؛ لكنه ليس تعريف Intel/AMD/NVIDIA أصليًا ولا يوفر تسريع 2D/3D. تفاصيل دعم framebuffer في بروتوكول Limine: https://github.com/Limine-Bootloader/limine-protocol/blob/trunk/PROTOCOL.md

## التحقق
تشغّل GitHub Actions اختبارات المضيف ثم اختبارَي QEMU (RTL8139 وE1000)، ويشترط كلاهما نجاح DHCP وPing البوابة وDNS وجلب صفحة HTTP محلية. لا تعتبر الميزة متحققة فعليًا إلا بعد نجاح المرحلتين في سجل Actions. هذه الاختبارات لا تثبت عمل كل بطاقة حقيقية أو دعم HTTPS والمواقع الحديثة.
